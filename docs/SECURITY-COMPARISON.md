## 2. Where EHC is ahead

1. **Mandatory, unguessable local API surface.** EHC: 127.0.0.1-only, per-launch random Basic-auth password, renderer never holds it, single-use SSE tickets minted in main, single instance, attach-first sharing. Peer reality: OpenCode's `serve`/`web` is **unauthenticated by default** and that gap enabled a drive-by RCE from a webpage ([Datadog](https://securitylabs.datadoghq.com/articles/opencode-upgrade-remote-code-execution/)). Many peers bind localhost servers with no auth at all. EHC's design makes that incident class structurally impossible.
2. **The model can never self-approve; approvals bind to an argument digest.** EHC strips authority from tool arguments and binds interactive approval cards to the exact argument digest. Peers lean on probabilistic review: Claude auto mode lets ~17% of overeager actions through ([Anthropic](https://anthropic.com/engineering/how-we-contain-claude)); Cursor documents "Auto-review is not a security boundary" ([docs](https://cursor.com/docs/agent/security/run-modes)); Warp's and Roo's approvers were bypassable outright (CVE-2026-48703, CVE-2026-82536). Digest binding also defeats approve-one-thing/run-another bait-and-switch in a way no peer documents.
3. **Fail-closed default posture.** EHC: fail-closed on unparsable permission config; sensing tools always ask. Peers default the other way: OpenCode's base policy is allow-everything with external directories open ([docs](https://opencode.ai/docs/permissions/)); Claude Code's sandbox is off by default and fails open ([docs](https://code.claude.com/docs/en/sandboxing)); Copilot local sandboxing is off by default ([docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes)); Goose default mode is full autonomy ([docs](https://block.github.io/goose/docs/getting-started/using-extensions)).
4. **Credential-file refusal by default.** EHC refuses secrets/`.env`/keys/runtime-descriptor to read, search, and commands. Claude Code's sandbox **reads the whole machine including `~/.ssh` and `~/.aws/credentials` unless you configure protection** ([docs](https://code.claude.com/docs/en/sandboxing)); Cline/Roo/Aider/Open Interpreter will read `.env` on request; a Windsurf/Cascade hijack read `.env` and shipped it out ([Witness](https://witness.ai/blog/windsurf-security)).
5. **OS-level detonation lane with host-resource detachment, on all three OSes.** WSL2 namespaces with host drives detached *and verified from inside the guest*, bubblewrap, Seatbelt, artifact into a private guest copy, tree-kill with pgrep confirmation. Peer sandboxes are consistently partial: Claude Code covers Bash only (file tools/MCP/hooks run outside), Codex runs stdio MCP servers outside its sandbox ([analysis](https://beri.net/article/openai-codex-sandbox-explained-seatbelt-bubblewrap-mxc-network-proxy-stdio-mcp-servers-requirements-toml)), Copilot's built-in file tools self-check "best-effort" outside the sandbox ([docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes)), and Claude Code on native Windows is **unsandboxed**.
6. **Containment hygiene.** Sibling/symlink/junction/8.3-alias-proof workspace checks on every FS tool. Anthropic itself lists symlink-resolution-before-validation as a lesson learned the hard way in Cowork ([source](https://anthropic.com/engineering/how-we-contain-claude)).
7. **Zero telemetry / zero cloud / no-PII audit log.** 2026 made this a differentiator: Warp's breach exposed **agent decision logs and telemetry** ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-dev-tool-telemetry-breach-warp-202/)); OpenCode's Console breach exposed brokered provider keys; Cursor's default Auto-review classifier reads local files from its backend ([docs](https://cursor.com/docs/agent/security/run-modes)). EHC's local audit log with rotation/health has no cloud copy to breach.
8. **Pinned SHA-256 download catalog, user-click only.** Peers install via npm ecosystem trust: Clinejection turned an npm publish token into code execution on ~4,000 dev machines ([post-mortem](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm)).
9. **Secrets at rest with Electron safeStorage (DPAPI/Keychain/libsecret) + settle-before-seal.** Ahead of Codex's default plaintext `auth.json` ([docs](https://learn.chatgpt.com/docs/auth)) and of anything storing keys in plaintext config; comparable to Cline's SecretStorage use, but EHC's IPC design means the renderer never holds the runtime credential at all.
10. **Scoped permission handlers at check AND request stage** (foreign webContents/subframes get nothing at both stages), CSP, pop-out allowlist, will-navigate/window-open denied — deeper Electron hardening than peers document; the only peer-analogue incidents (renderer/IPC attacks) are exactly what this forecloses.

## 3. Where EHC lacks or should adopt (prioritized)

### P1 — General egress proxy with domain allowlist + credential masking/delegation
**Gap:** EHC's network story is DNS pinning for BYOK/webfetch and a net-namespace lane for unclean input. There is no general-purpose egress control for *legitimate* tool work (package installs, git, API calls), and no way for a legitimate tool to use a secret without EHC handing over the real value or refusing.
**Peers:** Claude Code's sandbox proxy starts with an **empty allowlist**, supports `tlsTerminate`, and **masks credentials with sentinels, re-injecting real values only into approved hosts** (incl. SigV4 re-signing) ([docs](https://code.claude.com/docs/en/sandboxing)); Copilot CLI does the same placeholder-proxy pattern ([docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes)); Codex has a domain-rule network proxy with deny-beats-allow ([Inside the Codex sandbox](https://openai.com/index/inside-the-codex-sandbox/)). Anthropic's two most instructive incidents were **egress**: a phished prompt exfiltrated `~/.aws/credentials` 24/25 times because only environment controls can stop it, and an attacker key exfiltrated files *through* an allowed domain — "an allowlist may be better conceptualized as a capability grant" ([source](https://anthropic.com/engineering/how-we-contain-claude)).
**Adopt:** A local egress proxy in the detonation lane (and optionally for clean-tier network tools) with default-deny domains, per-approval domain grants, and sentinel-based secret re-injection (per-secret host allowlists).
**Cost/complexity:** The single biggest lift. TLS interception needs a local CA and breaks certificate-pinned clients; masking needs request parsing (Claude Code ships extract/decode/JWT-claim/AWS-SigV4 special cases). Budget weeks, not days; reuse patterns from the open-source `@anthropic-ai/sandbox-runtime` ([repo](https://github.com/anthropics/sandbox-runtime)).

### P2 — Signed releases, SBOM, and a hardened update path
**Gap:** EHC pins *its downloads* by SHA-256, but publishes (apparently) no signed artifacts, SBOM, or provenance for itself — and its own update path is unverified.
**Peers/standard practice:** cosign/Sigstore keyless signing, SLSA provenance, SPDX/CycloneDX SBOMs are now routine ([OWASP DevSecOps artifact signing](https://owasp.github.io/DevSecOpsGuideline/2-Process/2-3-Build/2-3-6-Supply-Chain-Security/2-3-6-2-Artifact-Signing-and-Provenance), [GitHub artifact attestations](https://docs.github.com/en/enterprise-cloud@latest/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity)); the OpenCode RCE was literally an **upgrade endpoint** accepting attacker content ([Datadog](https://securitylabs.datadoghq.com/articles/opencode-upgrade-remote-code-execution/)); OWASP ASI04 covers agentic supply chain ([OWASP Agentic 2026](https://genai.owasp.org/agentic-applications-2026/asi04-agentic-supply-chain-vulnerabilities)).
**Adopt:** cosign-sign release binaries; publish SBOM + SLSA-style provenance attestation per release; make EHC's updater verify signatures before install and never accept free-form URLs as upgrade targets.
**Cost/complexity:** Low–medium. Mostly CI work; signature verification in the updater is a few days.

### P3 — Tamper-evident, hash-chained approval/action journal
**Gap:** EHC's audit log is rotation/health-managed but not tamper-evident, and approval decisions (allow/ask/deny outcomes, session grants, revocations) aren't a first-class queryable history.
**Peers/toolkits:** OpenCode saves "Allow always" as durable project rules with a documented review burden ([docs](https://opencode.ai/docs/permissions/)); the 2026 monitoring ecosystem standard is hash-chained append-only ledgers: Tracekit's intent–reasoning–action audit with externally anchorable ledger ([arXiv 2609.35659](https://arxiv.org/html/2609.35659v1)), argus ([repo](https://github.com/Perseus-Computing-LLC/argus)), unworldly's "flight recorder" sealed trails ([repo](https://github.com/DilawarShafiq/unworldly)); tamper-evidence how-tos: hash chaining, Merkle trees, external anchoring ([Trussed guide](https://trussed.ai/resources/llm-audit-log-tamper-evidence-a-technical-guide)). CSA recommends exactly this plus minimization (AARM, AICM v1.1) ([CSA note](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-dev-tool-telemetry-breach-warp-202/)).
**Adopt:** Append-only, hash-chained approval journal (decision, argument digest, rule matched, outcome, timestamp), periodically anchor the head hash (e.g., to a local signed checkpoint file); add a review UI ("what did I approve last week?"). Keep the no-PII property.
**Cost/complexity:** Low. This is EHC's cheapest high-value win.

### P4 — Canary tokens / deception tripwires
**Gap:** EHC refuses known credential files, but has no mechanism to *detect* an agent (or injected content) probing for secrets it doesn't recognize — e.g., a renamed `.env.production.bak`, an unknown token file, or a decoy MCP tool.
**Peers/toolkits:** `canaryhook` plants decoy credential files that "trip on any read or exfiltration" ([repo](https://github.com/aiagentflow/canaryhook)); AgentShield layers decoy tools + honeytokens + egress monitoring ([repo](https://github.com/Yassin-H-Rassul/AgentShield)); Prismor fires on pre-read of registered canary paths ([repo](https://github.com/PrismorSec/prismor/blob/main/docs/canary.md)); Thinkst Canarytokens are the industry baseline ([skills entry](https://www.skillsdirectory.com/skills/costrict-plugins-repo-implementing-deception-based-detection-with-canary)). Anthropic itself dropped a canary string into a Slack thread under investigation because "in a world where agents read everything, the investigation tooling is also an attack surface" ([source](https://anthropic.com/engineering/how-we-contain-claude)).
**Adopt:** EHC can already see every read/search — synthesize canary files in plausible locations (fake AWS credentials, fake `.npmrc` token), and fire a loud local alert + audit entry on any touch, including via shell. Optionally inject canary strings into fetched content so exfil attempts are visible.
**Cost/complexity:** Low. Mostly UX (what happens on trip: block? alert? both).

### P5 — Sandboxing/scoping for MCP servers and long-lived helper processes
**Gap:** EHC gates `mcp_*` tool calls by permission pattern, but the MCP server *processes* themselves run with user authority (like every peer).
**Peers:** Everyone has this hole (Codex stdio MCP outside sandbox; Cowork deliberately moved local MCP out), but peers are building controls around it: Warp delivers secrets to factories "from an explicit per-agent allowlist" ([docs](https://docs.warp.dev/factories/infrastructure-and-security)); Copilot CLI can run local MCP/LSP inside the sandbox ([docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes)); MCP author guidance expects servers to rate-limit and scope tools ([Safeguard.sh on MCP tool permissions](https://safeguard.sh/resources/blog/mcp-tool-permission-design-least-privilege-tools)); the postmark-mcp incident shows a trusted-looking server exfiltrating via BCC — install-time approval did not help ([MITRE ATLAS AML.CS0053](https://atlas.mitre.org/studies/AML.CS0053), [Dark Reading](https://darkreading.com/application-security/malicious-mcp-server-exfiltrates-secrets-bcc)).
**Adopt:** Route each local MCP server's launch through the detonation lane's namespace/bwrap profile (read-only FS except a scratch dir, no network unless granted); per-server tool rate limits (e.g., N calls/minute) as a config knob.
**Cost/complexity:** Medium. Launch-path plumbing + breaking changes for servers needing broad FS (offer a documented escape hatch with explicit consent).

### P6 — Expose a read-only posture/introspection interface for independent monitors
**Gap:** EHC self-monitors; nothing external can verify it.
**Peers/toolkits:** A 2026 cottage industry watches agents from the outside: AEGIS (Windows desktop: process/file/TCP monitoring of agent processes, no plugin required) ([repo](https://github.com/antropos17/Aegis)), Thales `shadowai-watch` (passive OS-level discovery: every LLM API call and child process) ([repo](https://github.com/ThalesGroup/shadowai-watch)), Agent Beacon ([Help Net Security](https://www.helpnetsecurity.com/2026/02/27/new-infosec-products-of-the-month-february-2026/)), AgentDFIR (forensics: detect→collect→analyze) ([repo](https://github.com/efij/AgentDFIR)). Anthropic's Cowork lesson cuts both ways: isolation hid the agent from EDR, and they had to add pull-based OTLP export ([source](https://anthropic.com/engineering/how-we-contain-claude)).
**Adopt:** Document EHC's process signature (binary name, child-process patterns, port, cert pinning) so external monitors can recognize it; optionally expose a local read-only OTLP-style event feed (no content, just events) that an external monitor can pull.
**Cost/complexity:** Low (documentation) / medium (event feed).

### P7 — Untrusted-content treatment in the clean tier (spotlighting, summarization)
**Gap:** EHC's tasking doesn't mention any content-level prompt-injection defense for fetched pages, file contents, or MCP results that enter the *clean* tier.
**Peers:** Claude Code runs WebFetch through a **separate model call** so the agent sees a summary, not raw page text ([docs](https://code.claude.com/docs/en/security)); Anthropic's enterprise guide describes "warning and anchoring" — delimiting untrusted content and telling the model the user's request is still the task ([claude.com guide](https://claude.com/resources/articles/enterprise-guide-to-securing-coding-agents)); the research frontier is CaMeL/dual-LLM: capabilities + a trusted control LLM that never sees untrusted data, proven to defeat injection by design ([arXiv 2503.18813](https://arxiv.org/abs/2503.18813), [Willison](https://simonwillison.net/2025/Apr/11/camel)).
**Adopt:** (a) Wrap all externally-sourced content in explicit untrusted delimiters with a standing instruction; (b) for webfetch, offer a summarize-then-ingest mode (EHC's BYOK Vision stack makes a second small-model call cheap); (c) never let fetched content name files to read or commands to run — express any such suggestion as a *suggestion card* that must go through the normal permission gate (which EHC already has — close the loop by marking the provenance).
**Cost/complexity:** Low for delimiting/provenance; medium for summarizer mode.

### P8 — Optional auto-review lane (local classifier) for approval fatigue
**Gap:** EHC's always-ask-for-dangerous posture is safer but will hit the fatigue wall peers measured: Anthropic found users approve ~93% of prompts, and shipped auto mode to compensate ([source](https://anthropic.com/engineering/how-we-contain-claude)); Cursor/Codex both ship classifier review ([Cursor](https://cursor.com/docs/agent/security/run-modes), [Codex auto-review](https://developers.openai.com/codex/sandboxing/auto-review)).
**Adopt:** An *opt-in* "auto-approve inside verified sandbox + read-only commands" tier, using EHC's existing OS lane as the compensating control (this is exactly Anthropic's architecture: classifier inside sandbox, not instead of it). If a local small model is available, it can classify borderline commands; otherwise restrict auto-approval to EHC's declarative read-only batch and sandboxed commands.
**Cost/complexity:** Medium. The classifier adds a probabilistic component — keep it strictly *inside* the sandbox so its misses don't matter (Anthropic's stated design: "one layer of defense-in-depth inside a sandbox, not a substitute for one").

### P9 — Secrets masking for legitimate workflows
**Gap:** EHC refuses credential files outright. Safer than peers, but it forces users who legitimately need `gh`/`aws`/`npm publish` to weaken the deny, which is how good defaults die.
**Peers:** Claude Code mask-with-proxy and Copilot CLI placeholder-proxy (P1); Warp's per-agent secret allowlist ([docs](https://docs.warp.dev/factories/infrastructure-and-security)); community tools hand keys to single processes without entering the conversation ([api-key-manager](https://github.com/paperfoot/api-key-manager)).
**Adopt:** A "delegated secret" primitive: user registers a secret once (safeStorage), names the tool/prefix allowed to use it; EHC injects at process spawn (env), scrubs from output, never shows it to the model. This complements rather than replaces file refusal.
**Cost/complexity:** Medium; depends partly on P1's proxy for the network path.

### P10 — Stronger isolation tier (microVM) for high-paranoia runs
**Gap:** EHC's lane is namespace/bwrap/Seatbelt — same kernel. The industry's strong tier is microVMs.
**Peers:** claude.ai uses gVisor containers ([Anthropic](https://anthropic.com/engineering/how-we-contain-claude)); Copilot cloud + Devin use per-session VMs/machines ([GitHub](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/about-cloud-sandboxes), [Devin](https://docs.devin.ai/enterprise/deployment/overview)); Firecracker/gVisor tradeoffs are well mapped for agent workloads ([Northflank](https://northflank.com/blog/how-to-sandbox-ai-agents), [Blaxel](https://blaxel.ai/blog/gvisor-vs-firecracker-agent-sandboxing)); even Aider's community asked for QEMU microVM test execution ([#4882](https://github.com/Aider-AI/aider/issues/4882)); Claude Cowork ships a full local VM on the desktop ([Anthropic](https://anthropic.com/engineering/how-we-contain-claude)).
**Adopt:** An optional "sealed" run mode: WSL2 utility VM (Windows), Lima/Tart-ish VM (macOS), or Firecracker-class (Linux) with only the workspace mounted read-write-no-delete. Anthropic's mount-mode design (read-only / read-write / **read-write-no-delete**) is directly copyable.
**Cost/complexity:** High. Boot latency, image management, toolchain availability inside the guest; EHC's WSL2 lane is already 80% of the way on Windows.

### P11 — Native Windows sandbox fallback
**Gap:** EHC's detonation lane depends on WSL2. If WSL2 is unavailable/broken, what happens? (Fail closed is required.)
**Peers:** Codex built a full native Windows sandbox (write-restricted tokens, synthetic SIDs, dedicated local users, firewall rules, elevated setup) after rejecting AppContainer/MIC/Windows Sandbox as wrong-shaped ([OpenAI](https://openai.com/index/building-codex-windows-sandbox/)); Copilot CLI uses MXC, and is explicit that Windows proxy enforcement is advisory ([docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes)); Claude Code on native Windows is unsandboxed and tells you to use WSL2 ([docs](https://code.claude.com/docs/en/sandboxing)).
**Adopt:** Verify EHC fails closed (refuses execution) when WSL2 is missing; a native restricted-token fallback is optional and should be honest about the advisory-only network story.
**Cost/complexity:** Fail-closed check: low. Native sandbox parity: high (see OpenAI's four-binary architecture).

### P12 — Lower-priority adoptions
- **Org/managed policy layer** (hard-deny above workspace config): Claude managed settings, OpenCode `policies`, Gemini policy engine, Warp admin panel, Copilot managed settings all support "operator can't talk the agent out of it." If EHC ever ships team use, add a read-only policy file that overrides workspace config. Cost: low. ([Claude managed settings](https://code.claude.com/docs/en/security), [OpenCode policies](https://opencode.ai/docs/permissions/), [Gemini policy engine](https://geminicli.com/docs/reference/policy-engine))
- **MCP client consent UX per spec:** SEP-1024 requires displaying the exact command, untruncated, with all arguments before running a local server ([SEP-1024](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/a4ea0ac5/seps/1024-mcp-client-security-requirements-for-local-server-.md?plain=1)); OWASP's cheat sheet reinforces per-tool consent + human-in-the-loop ([OWASP MCP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html)). EHC's approval cards already exceed this — add the *server-install* consent card if missing. Cost: low.
- **Pre-trust hardening:** Anthropic's lesson that project config parsing before the trust dialog was repeatedly exploitable ("treat project-open, config-load, and localhost listeners like inbound internet traffic") ([source](https://anthropic.com/engineering/how-we-contain-claude)). Audit EHC's workspace-config load ordering against this. Cost: low.
- **Keychain ACL hygiene:** Silverfort showed Claude Code's Keychain item is readable by any same-user process without re-auth ([Silverfort](https://silverfort.com/blog/skipping-the-lock-a-claude-code-cli-weakness-lets-any-macos-process-read-stored-credentials)); VS Code's safeStorage is AES-128-CBC and readable by any extension ([Netwrix](https://netwrix.com/en/resources/blog/ai-coding-assistant-credential-storage-risks)). EHC uses safeStorage — verify items aren't world-readable and that another local process can't coerce EHC into decrypting (its auth model helps here; document it).

## 4. Adjacent security structures for AgentWatch-style monitoring

What independent-monitoring toolkits do, and what EHC should track as a standard:

**Deception / canaries**
- Decoy credential files that trip on read or exfil attempt: [canaryhook](https://github.com/aiagentflow/canaryhook).
- Layered deception: decoy tools only a compromised agent would call; honeytokens in env; egress flagging: [AgentShield](https://github.com/Yassin-H-Rassul/AgentShield).
- Pre-read/post-read canary interception: [Prismor canary docs](https://github.com/PrismorSec/prismor/blob/main/docs/canary.md).
- Commercial baseline: Thinkst Canarytokens ([integration example](https://www.skillsdirectory.com/skills/costrict-plugins-repo-implementing-deception-based-detection-with-canary)).

**Process posture / passive OS monitoring**
- AEGIS: external Windows monitor of agent processes, sensitive-file observations, TCP connections — explicitly "no agent plugin or subscription" ([repo](https://github.com/antropos17/Aegis)).
- `shadowai-watch` (Thales): passive Linux discovery/auditing of what agents actually do — LLM API calls, child processes ([repo](https://github.com/ThalesGroup/shadowai-watch)).
- Agent Beacon: open-source telemetry layer recording what local agents do ([Help Net Security](https://www.helpnetsecurity.com/2026/02/27/new-infosec-products-of-the-month-february-2026/)).
- AgentDFIR: one-command forensics (detect → collect → analyze → browse) across Claude Code, Codex, Cursor, Gemini, Copilot ([repo](https://github.com/efij/AgentDFIR)).
- EHC hook: EHC's tree-kill-with-pgrep and per-launch random ports are process-posture facts an external monitor can verify — publish them.

**Ledger anchoring / tamper evidence**
- Hash-chained append-only ledgers for agent actions: [argus](https://github.com/Perseus-Computing-LLC/argus), [quledger](https://github.com/quome-cloud/quledger); intent–reasoning–action cross-checked ledger with external anchoring: [Tracekit, arXiv 2609.35659](https://arxiv.org/html/2609.35659v1); sealed "flight recorder" trails claiming ISO 42001 alignment: [unworldly](https://github.com/DilawarShafiq/unworldly).
- Techniques: hash chaining, Merkle trees, signatures, timestamping, WORM storage ([Trussed](https://trussed.ai/resources/llm-audit-log-tamper-evidence-a-technical-guide)).
- Governance framing: CSA AARM spec + AI Controls Matrix v1.1 (LOG/DSP/CEK/STA domains) + MAESTRO threat modeling ([CSA note](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-dev-tool-telemetry-breach-warp-202/)).

**Prompt-injection defense research (context for monitoring signals)**
- CaMeL (DeepMind): capabilities + dual-LLM control plane; injection defeated by design, not detection ([arXiv 2503.18813](https://arxiv.org/abs/2503.18813); [Willison's explainer](https://simonwillison.net/2025/Apr/11/camel); computer-use extension [arXiv 2601.09923](https://arxiv.org/html/2601.09923v1)).
- OpenAI: layered defenses for Operator/Atlas — user takeovers, allowlists, "Lockdown Mode" ([system card](https://openai.com/index/operator-system-card), [Atlas hardening](https://openai.com/index/hardening-atlas-against-prompt-injection), [prompt injections overview](https://openai.com/index/prompt-injections)); Google's Bug Hunters on task injection ([bughunters.google.com](https://bughunters.google.com/blog/task-injection-exploiting-agency-of-autonomous-ai-agents)).
- Anthropic: containment-first doctrine, egress-as-capability, canary strings, ~83% classifier catch rate ([engineering post](https://anthropic.com/engineering/how-we-contain-claude)); agent containment best practices with egress allowlists (private beta) ([support article](https://support.claude.com/en/articles/17316099-agent-containment-best-practices-prompt-injection-private-beta)).

**MCP security guidance**
- Spec principle: hosts must obtain explicit user consent before invoking any tool; human must be able to deny ([MCP spec 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28#key-principles), via [OWASP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html)).
- SEP-1024: local-server consent must show exact command, untruncated, all arguments ([SEP-1024](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/a4ea0ac5/seps/1024-mcp-client-security-requirements-for-local-server-.md?plain=1)).
- Per-tool scopes and dynamic consent: [WorkOS pattern guide](https://workos.com/blog/mcp-authorization-patterns-per-tool-scopes); servers should validate inputs and rate-limit invocations ([Safeguard.sh](https://safeguard.sh/resources/blog/mcp-tool-permission-design-least-privilege-tools)).
- Incidents proving install-time consent insufficient: postmark-mcp BCC exfiltration ([MITRE ATLAS AML.CS0053](https://atlas.mitre.org/studies/AML.CS0053), [Semgrep](https://semgrep.dev/blog/2025/so-the-first-malicious-mcp-server-has-been-found-on-npm-what-does-this-mean-for-mcp-security/)).

**Sandboxing standards landscape (what EHC's lane is measured against)**
- Linux: bubblewrap (unprivileged namespaces+seccomp; "not a complete, ready-made sandbox with a specific security policy") ([README](https://raw.githubusercontent.com/containers/bubblewrap/v0.11.0/README.md)); firejail (SUID, profiles) ([FAQ](https://github.com/netblue30/firejail/wiki/Frequently-Asked-Questions)); comparison writeups ([dev.to](https://dev.to/sandscale/nsjail-bubblewrap-and-firejail-compared-three-linux-process-sandboxes-from-their-own-docs-16fj)); Landlock+seccomp as the newer Cursor/Qwen choice ([Cursor docs](https://cursor.com/docs/agent/security/run-modes)).
- macOS: Seatbelt/`sandbox-exec` **deprecated by Apple but still the substrate under Claude Code, Codex, Cursor, Copilot CLI, Gemini CLI** ([analysis](https://github.com/kainkalju/analysis/blob/main/macos-seatbelt.md), [Infralovers](https://www.infralovers.com/blog/2026-02-15-sandboxing-claude-code-macos/), [Forkbench](https://forkbench.com/blog/sandbox-ai-coding-agent-macos)).
- Windows: AppContainer (capability SIDs; strong but wrong shape for open-ended agent workloads per OpenAI) ([MS Learn](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation), [OpenAI](https://openai.com/index/building-codex-windows-sandbox/)); write-restricted tokens + synthetic SIDs + firewall + dedicated users (Codex); MXC (Copilot CLI) ([microsoft/mxc](https://github.com/microsoft/mxc)).
- Strong tier: gVisor (userspace kernel Sentry) vs Firecracker (KVM microVM) for agent sandboxes ([Northflank](https://northflank.com/blog/how-to-sandbox-ai-agents), [AWS Builder Center](https://builder.aws.com/content/3ADDWTtyI2gevtzY9d2vzULAxzS/secure-agent-sandboxes-on-eks)).

**Secret-management practice for local dev tools**
- Plaintext-by-default credential stores remain common: Codex `auth.json` 0600 plaintext ([docs](https://learn.chatgpt.com/docs/auth)); Claude Code keychain ACL weakness ([Silverfort](https://silverfort.com/blog/skipping-the-lock-a-claude-code-cli-weakness-lets-any-macos-process-read-stored-credentials)); VS Code safeStorage cross-extension exposure + plaintext MCP settings synced to cloud ([Netwrix](https://netwrix.com/en/resources/blog/ai-coding-assistant-credential-storage-risks)).
- Emerging pattern: secrets injected per-process, never entering the model conversation ([api-key-manager](https://github.com/paperfoot/api-key-manager), [llm-key-ring](https://github.com/yottayoshida/llm-key-ring)); decoy-value vaults ([cloak](https://github.com/danieltamas/cloak)).
- EHC's safeStorage + env-scrub is at the good end; P9 (delegated injection) completes the picture.

**Supply-chain / pinned-download practice**
- Standard: Sigstore/cosign keyless signing, SLSA provenance, SBOM (SPDX/CycloneDX), GitHub artifact attestations ([OWASP](https://owasp.github.io/DevSecOpsGuideline/2-Process/2-3-Build/2-3-6-Supply-Chain-Security/2-3-6-2-Artifact-Signing-and-Provenance), [GitHub docs](https://docs.github.com/en/enterprise-cloud@latest/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity), [Chainguard explainer](https://chainguard.dev/supply-chain-security-101/sboms-vs-attestations)).
- Motivating incidents: Clinejection npm-token compromise ([post-mortem](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm)); upgrade-endpoint RCE ([Datadog](https://securitylabs.datadoghq.com/articles/opencode-upgrade-remote-code-execution/)).

**Standards EHC should track**
- [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/top-10-for-agentic-applications-2026/) (ASI01–ASI10; e.g., ASI02 tool misuse, ASI04 supply chain) and the [OWASP Agentic Skills Top 10](https://owasp.org/projects/agentic-skills-top-10) (AST06: "without a sandbox, every skill is a potential full-system compromise").
- [OWASP MCP Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html).
- CSA: [AI Controls Matrix v1.1](https://cloudsecurityalliance.org/artifacts/ai-controls-matrix-v1-1), [MAESTRO](https://cloudsecurityalliance.org/blog/2025/02/06/agentic-ai-threat-modeling-framework-maestro), AARM ([CSA note](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-dev-tool-telemetry-breach-warp-202/)).
- [ISO/IEC 42001](https://www.iso.org/standard/42001) (AI management systems); NIST log-management baseline [SP 800-92](https://csrc.nist.gov/pubs/sp/800/92/final) and the [NIST agent identity/authorization project](https://www.nccoe.nist.gov/projects/software-and-ai-agent-identity-and-authorization); six-agency guidance on careful adoption of agentic AI (ACSC/CISA/NCSC, Apr 30 2026) ([PDF](https://media.defense.gov/2026/Apr/30/2003922823/-1/-1/0/CAREFUL%20ADOPTION%20OF%20AGENTIC%20AI%20SERVICES_FINAL.PDF)) — all referenced in [Anthropic's containment post](https://anthropic.com/engineering/how-we-contain-claude).
- [MITRE ATLAS](https://atlas.mitre.org/) for agent-attack case studies (e.g., [AML.CS0053](https://atlas.mitre.org/studies/AML.CS0053)).
